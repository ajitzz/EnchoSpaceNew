# HARVO — explicit review of prepared campaign images

13 September 2026. Extension of the bounded image/storage implementation, authorized as independently executable M5 work. Guest checkout/legal gates remain unchanged. Root owns shared campaign/AI/provider/runtime/router/worker integration; this owner adds migration015, creative workflow/CDN verification modules, host/admin components and isolated tests.

## Impact and plan before code

The preparation/storage helpers now generate real source-preserving images and checksum-verified objects. Current campaign approval still binds original media. Completing the integration requires a separate immutable derivative authority, not a browser-submitted URL, a generated placeholder, a new guest gallery field or silent substitution after approval.

1. Persist queued preparation requests and exact normalized source/derived bytes with their full source/output manifest. Every record belongs to a real host, listing and approved source asset. Per-host idempotency and bounded request quotas prevent duplicate work. A worker handles one image format per claim, with short PostgreSQL transactions, fences, an expiry and bounded attempts; no network or image processing runs inside a transaction.
2. Conditional S3 writes retain exact known keys and checksum evidence. Before host review, fetch the configured CDN object itself and compare actual bytes with the persisted output digest/length. Failed/missing storage or CDN verification remains explicit. Unknown writes cannot approve an image; retries only use the same immutable bytes/keys.
3. Host review shows actual saved source/derivative bytes, captures rights and the exact manifest hash and then submits to admin. Admin separately reviews that exact output/source pair and records a decision, appearance confirmation and note. Source ownership, approved status, current listing hash and current bytes remain checked. Human review is not provider policy approval.
4. Root adds optional derivative ID plus manifest hash to a campaign draft, allowed only for the first selected Meta IMAGE. The resolved trusted derivative is retained in immutable revision `listing_snapshot.campaignCreative`; original listing media and listing hash stay original. Root re-resolves at save, AI evaluation, content approval and publication. AI/admin inspect the actual derivative pixels. A trusted typed provider verifier checks approval/source/hash inside the provider claim transaction; client fields cannot disable the ordinary media check.
5. `verifyForPublishing` performs fresh bounded CDN exact-byte verification outside any DB transaction, checking authority before and after. `resolveForCampaign` repeats persisted approval/source binding inside the caller's transaction. No new provider write is enabled merely because preparation succeeds.

API contract agreed with root: POST `/creatives`; GET `/creatives` and `/admin/creatives` with bounded keyset paging; authenticated GET `/creatives/:id/image?view=SOURCE|DERIVATIVE`; POST `/creatives/:id/confirm`; POST `/admin/creatives/:id/review`. The host panel receives listing/source/selection and explicitly returns a derivative selection; the admin workspace owns derivative moderation. No property gallery field changes.

Regression risks: cross-host reads, stale source/listing approval, source/derivative byte substitution, replayed requests or stale worker completion, wrong MIME/SSRF at CDN, post-review CDN replacement and authority differences between preview/AI/provider. Tests must use real disposable PostgreSQL, real fixture image bytes and injected storage/CDN responses. Do not start remote services, use real S3 or substitute a fake accepted derivative. Rollback disconnects the new workflow and leaves immutable evidence/objects intact; approved original media publishing remains supported.

## Implementation and verification

The service, routes, worker maintenance task and host/admin studio are now connected. `POST /creatives` creates durable per-format requests; the worker prepares one exact format per fenced claim, stores immutable S3 evidence and verifies the configured CDN bytes; host confirmation advances the record to independent administrator review; an approved derivative can be selected only for the first Meta image and is re-resolved at every campaign revision boundary and publishing attempt. The route serves protected source/derivative bytes for review and never treats a browser URL, configured hostname or provider PAUSED response as approval.

Focused creative preparation, storage, binding, workflow and Meta-provider suites pass under Node 24. The full path still requires an actual configured S3/CDN, Linux worker run, real Meta app/account permissions and a bounded pilot before M5 or live-provider acceptance can change. Video transcoding, generated imagery, automatic DCO and placement-specific provider acceptance remain separate work.
