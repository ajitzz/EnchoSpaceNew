# R2-01 canonical notification lane impact

28 September 2026 · bounded implementation authorized by the implementation lead · no release acceptance.

**Preserved authority.** Migration 037's held-transaction message trigger assigns the notification UUID and `conversation-message:<message_id>` dedupe key from globally unique canonical message identity. RLS/queue-only worker grants and the stored fingerprint remain authoritative. Do not alter applied migration bytes or generic dedupe semantics. Existing finance and other provider queues remain unchanged.

**Proven source risks to reproduce before repair.** `DurableOutbox.inTransaction` lets a failed rollback mask the original error and returns an uncertain connection to its pool. A COMMIT error has no distinct contract although its persisted result may be unknown. The notification worker checks readiness before claiming but not after the claim; a changed worker grant/policy must prevent the next socket hint.

**Bounded change.** Own `src/lib/platform/durableOutbox.ts`, `src/server/conversation/notificationWorker.ts`, their focused PostgreSQL tests and local process fixture. Subsequent ownership includes the narrow `conversationReadiness.ts` repair: neither runtime nor worker mode can certify a table-owner pool. An existing owner-negative test failed during reproduction; the inspection path incorrectly treated owner authority as ready. Root owns the separate test-only prototype import guard and build/CI wiring. No API, UI, schema, invoice, money policy, provider effect or customer message is added.

**Failure contract.** Preserve the exact original pre-COMMIT exception even if rollback fails; discard any connection whose transaction cleanup is uncertain. Once COMMIT has been attempted, expose a stable typed unknown-outcome error with the original error as its non-enumerable cause, discard the connection and never blindly retry that transaction. The hint worker reports uncertainty without overwriting the durable row. On restart, a successful commit stays complete; an uncommitted local hint recovers only after lease expiry using the same notification identity. These UI hints remain at-least-once, not an exactly-once customer delivery guarantee.

**Validation.** Node 24 plus sanitized `scripts/testing/run.mjs`, one/two files per run. Real disposable PostgreSQL separate LOGIN roles, injected transport faults before/after actual COMMIT, failed rollback, post-claim authority revocation, stale fencing, separate child-process competing workers and restart. Retain failed and repaired evidence separately. Test the import guard against fixture static/transitive/dynamic imports and the current repository.

**Compatibility / rollback.** Successful public methods and schema remain compatible. New stable unknown-outcome codes require callers to reconcile, not translate into retry. Disable the notification worker if regressions occur while retaining queued intents/events and exact IDs. Never roll back to generic offline replay, prototypes, or process-local dedupe. R2-01 remains partial until other mounted domain command routes are reviewed and accepted.

## Local result and limits

- Reproduced three transaction regressions (original rollback error masked; COMMIT uncertainty before/after real commit), post-claim revocation dispatch and the pre-existing worker owner-pool acceptance defect. Retained failing receipts separately.
- Reused `verifyRuntimeDatabaseAuthority` from the shared R2 readiness lane: actual session/current login and all reachable memberships must be safe, including NOINHERIT and owner-through-SET-ROLE. Runtime/worker owner readiness now fails. The two valid fixture LOGIN roles remain ready.
- Added stable runtime unknown-outcome projection in `notificationRuntime.ts`; original PG causes, IDs, message text and credentials are never copied into the runtime report. Normal retries keep their durable limits; uncertain commits await durable-state/lease recovery.
- Final reviewed canonical tests: **37/37** (27 real-worker cases plus 10 generic outbox cases), Node 24 sanitized runner. Adjacent restricted-role conversation and service-case compatibility suites: **58/58**. Scoped strict TypeScript, scoped lint and diff check passed. These are local disposable PostgreSQL results, not Neon/staging/provider evidence.
- Independent source review identified a further NOINHERIT capability gap: safe ancestor role flags alone do not exclude extra table/column/function/sequence grants reachable through SET ROLE. Readiness now verifies exact current-role requirements and forbidden capability unions across reachable roles. Eight concrete negative cases cover both worker and consumer identities; no current required grant was weakened.
- Distinct Node processes demonstrate a single simultaneous claim, actual exit after socket-hint acceptance, restart after lease expiry using the same notification ID, and no dispatch once durable success exists. A stale pre-effect claim and post-effect lease loss have separate tests.
- The worker reauthorizes after claim and before each hint using a held connection for catalog/current-claim reads. It does **not** serialize permission revocation against the instant of socket emission; revocation after the last check can race an already authorized hint. No DB lock is held across a socket effect. Recipients must reauthorize canonical content fetches, and hints remain at-least-once, content-free optimization. This is not customer delivery or exactly-once proof.
- Full catalog checks per hint add database round trips; no performance SLO or remote latency certification is claimed. Optimize only while preserving equivalent current-authority proof and test coverage.
- No schema/migration, provider, paid pool, customer messaging or deployment mutation occurred. The deployed role/credential identity remains an external gate. The rest of R2-01 (domain adoption map, remaining route semantics and prototype guard) remains separately owned/open.
