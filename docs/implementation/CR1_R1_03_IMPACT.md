# R1-03 impact note — offline replay retirement

Status: READY_FOR_REVIEW; no acceptance or deployment claim.

Baseline: HEAD `0e4c6fec2fe86f1b793760c5f7a3daf08bbf7508` with pre-existing staged work retained. Audit A05 and original CR1 P1.4/P1.7/P3.6 govern this slice.

Source of truth: `lib/syncService.ts` already allows actor-scoped, credential-free wishlist and canonical inquiry retries with stable client-event identity. Preserve it. `vite.config.ts` independently installs Workbox `api-syncQueue` for generic POSTs, storing request headers/body in IndexedDB `workbox-background-sync` / `requests`. This path does not share actor logout fencing and includes workforce/admin operations. Existing auth cleanup only clears idb-keyval actor keys.

Planned change: retire all service-worker mutation replay; retain safe GET caching and existing explicit actor intent allowlist. Move worker source to typed `src/sw.ts` with the same `/sw.js` registration URL; purge only the retired Workbox queue before activation/claim, during client startup and identity transitions. A new page controlled by an unrecognized old worker must complete an update handshake before mounting authenticated UI. Cross-tab identity changes purge old actor intents; current-session checks fence future safe replay. No credentials are transmitted to a worker or persisted in the queue.

Implemented refinement (supersedes the initial timestamp cutoff): logout records a unique cryptographic revocation nonce in localStorage before asynchronous IndexedDB deletion. Each queued intent captures separate actor/global generation tokens and replay requires exact equality. This avoids wall-clock rollback and non-atomic cross-tab counter updates. Numeric historical markers remain readable; legacy commands without a generation are eligible only while both markers are initial zero. The markers contain no credential or message. Fresh same-actor token rotation preserves stable unresolved message events; logout/account switch retires them. AuthContext rejects in-flight identity responses after a token change and clears stale cross-tab UI before server identity verification.

Independent review refinements: the session snapshot now captures its replay cutoff so a logout/relogin with the same token cannot promote an in-flight prior intent into the new session. Same-ID profile refreshes preserve pending messages. Unknown actor cleanup records a global cutoff before attempting deletion. API image paths are now NetworkOnly; runtime image caching is restricted to unauthenticated public build assets and Unsplash. Retired broad image-cache names are deleted alongside the legacy Workbox queue. These findings were identified by the separate IAM implementation agent during bounded review; this note is not that reviewer's acceptance.

Affected source: Vite PWA configuration, typed worker and retirement helper, client bootstrap/AuthContext and scoped sync cleanup; targeted unit/browser tests. No API/schema/provider/finance change. API mutation errors remain online-only unless the existing canonical allowlist explicitly permits retry.

Security/compatibility: old generic commands are unsafe to migrate because their original actor intent and outcome cannot be proved. Delete local requests, not server effects. A request already dispatched by an old worker cannot be recalled by client code; server authorization, revocation and idempotency remain required. An offline browser still serving the entire old application cannot receive a new security patch until it reconnects; rollout must track minimum client/worker version and invalidate compromised server sessions where necessary. The new application fails closed if an old controlling worker cannot update.

Validation: sanitized Node 24 targeted actor-sync tests; isolated local Chromium using the production-built worker, actual IndexedDB, legacy worker upgrade, multiple tabs, logout/account switch, reconnect and credential inspection. All network targets limited to a disposable localhost HTTP fixture. No remote build checks, provider calls or customer messages.

Observed results: 34 actor-sync tests and ten Chromium scenarios pass against the production Vite PWA worker pipeline with a local fixture page using real AuthContext/sync functions. This is not a full Encho browser journey or deployed-client rollout receipt. The legacy positive control uses actual Workbox generation and observes a synthetic bearer in its queue. Browser background-sync permission is deliberately denied until upgrade; after upgrade a CDP sync dispatch confirms that the retired queue has no replay. Cases include waiting/interrupted update, both-tab claim, privileged offline requests, logout/account switching, same-actor profile refresh, private-image cache denial, HTTP401 reauthentication, ambiguous canonical-message reconciliation, and fail-closed upgrade refusal. Scoped lint and strict TypeScript pass. See `CR1_R1_03_LOCAL_RECEIPT.json` for command/provenance details.

Build boundary: Vite now sets `envDir: false`; public deployment variables must be explicit. The PWA uses injectManifest without a Workbox mutation route. `scripts/testing/tsconfig.offline.json` provides strict checking for this slice; the repository-wide milestone gates remain separate.

Rollback: disable/unregister the service worker and serve the online-only application if upgrade fails. Never restore generic POST background sync. Keep canonical inquiry event IDs for reconciliation of unknown server outcomes. New worker must keep stable `sw.js` scope so existing registrations upgrade.

Follow-up peer review: a backward wall-clock adjustment before logout defeated timestamp-only persisted queue invalidation when IndexedDB deletion failed. The IAM agent implemented the generation-pair repair and reproduced the failure first; the original offline implementation agent then identified the remaining cross-tab counter ABA risk and independently reviewed the final unique-nonce repair. Final combined actor/browser run: **44/44** (34 actor tests plus 10 production-built worker browser fixtures); independent actor rerun: **34/34**. Strict scoped TypeScript and narrow follow-up lint pass. Prior failed/qualified evidence is preserved. This restores a bounded peer-review pass for the source/local slice, not independent release acceptance or deployment certification.
