# W2-P0 impact and red receipt — 4 October 2026

**Base:** W1 canonical development `4010828e5c242edb270c544f29c68cdb55b18e19`. This is a local W2 investigation, not an accepted W2 implementation or deployment.

**Reproduced defect:** `scripts/testing/w2-hold-without-quote.mjs` builds and starts the mounted server against fresh disposable PostgreSQL. It creates a canonical room, accepts an exact W1 offer revision, establishes inventory, and posts directly to `/api/v2/stays/holds` with room ID/dates but no quote. The route returns HTTP 201; one `booking_holds` row and three held `inventory_days` units exist. The assertion deliberately fails. Receipt: `/tmp/encho-w2-p0-red-actual.log` on the local host. This proves the missing quote boundary without relying on a mocked service.

**Source of truth and impact:** W1 `sellable_offers` plus immutable `sellable_offer_revisions` are the commercial input authority. The mounted route in `server.ts` currently passes request room/date/quantity straight to `acquireHold` in `src/services/inventoryHoldService.ts`. That service owns principal-bound idempotency, ordered row locks, all-night atomic inventory mutation, and the existing 600-second hold expiry; retain those mechanisms. The 041 `stays_quotes` table has no accepted-offer binding and requires tax and payable total, so its current shape cannot truthfully represent the legally ungated W2 room subtotal. Its separate `stays_holds` table does not own physical inventory and must not become a second inventory authority.

**Smallest canonical correction to implement next:** In a new, locally tested additive migration after 049, evolve `stays_quotes` as the *one* itinerary quote table: add an exact `(offer_id, offer_revision)` foreign key, holder principal, accepted nightly amount, price basis, source fingerprint, and a quote kind. Permit `tax_paise` and `total_paise` to be absent only for accepted-offer room-subtotal quotes; preserve the original non-null arithmetic for historical legacy rows. Bind `booking_holds` to `stays_quotes.id`, retaining historical unbound rows only as history. Do not route W2 through `stays_holds` or the synthetic commerce engine. A new server quote command must validate exact current accepted revision, date/effective scope, occupancy, room/property link and all itinerary nights, and persist an immutable principal-bound subtotal snapshot with an expiry no later than the existing hold TTL or offer expiry. It must not calculate tax or a payable total.

The mounted hold command must require the quote ID. Within the **same held PostgreSQL transaction** that locks inventory days and inserts `booking_holds`, lock/read the quote and verify principal, expiry, exact room/dates/guest/quantity contract, accepted revision and fingerprint; reject mismatch/stale authority before incrementing capacity. Include quote identity in the hold idempotency fingerprint and persist it on the hold row. A replay with a different quote must conflict. Client monetary fields remain ignored or rejected. Existing W1 revisions remain immutable. If a successor/revision makes a quote stale before hold, fail closed and request a new quote; do not silently substitute a price.

**Compatibility/security:** This changes the W2 hold API contract, not W0/W1 public price truth. Historical `booking_holds` remain readable/releasable; no new unquoted hold may be created by the mounted route. Migration must preserve applied SQL bytes, RLS/grants, and existing quote rows. Validate with restricted LOGIN roles and a real disposable PostgreSQL cluster. Do not apply to primary Neon or enable payment. The route must not claim a confirmed booking or payable total.

**Verification and rollback:** First turn the red script green with zero rows/units for an unquoted POST; then prove quote→hold, forged/foreign/expired/stale quote rejection, same-key replay and changed-quote conflict, two independent connections competing for one final room, all-or-zero multi-night conflict and expiration recovery. Run mounted API, M4 inventory, W1 offer/public tests, typecheck, lint and offline build. A local rollback can disable new quote and hold commands while leaving historical holds releasable and sweepable; never drop accepted facts or held inventory merely to roll back code.
