# R2-02 direct-export legacy DDL containment — impact before code

**Source of truth.** Migration files and the explicit migration runner own schema changes. The existing local-disposable gate covers startup and route helper bootstrap, but source review identified two exported `server.ts` functions that can be invoked directly: `ensureMarketingSchema()` and `processMetaReconciliation()`. Both contain inline `CREATE`/`ALTER` statements. The latter also owns legacy provider reconciliation effects. A guarded interval does not guard a direct import/call. This is a structural reachability finding, not evidence of a remote invocation.

**Change boundary.** Add a fail-closed check at each exported function entry before DDL, advisory locks, remote provider calls or data mutation. Preserve the credential-scrubbed test fixture and the explicit disposable-local path only where their existing tests need it. Do not silently return success for a denied invocation. Do not alter versioned migrations, canonical finance or the dedicated marketing worker. Keep the function's existing return contract for authorized local fixtures; classify any denied call as unavailable.

**Affected surfaces.** `server.ts` two exported functions and new focused guard tests; direct-import tests are the compatibility concern. No public API success contract or schema number changes. A remote development process with primary `.env` must be unable to enter inline DDL through either direct export. A local-only database URL does not itself prove that provider credentials are safe; provider effects require an even narrower sandbox or explicit fake transport.

**Validation and rollback.** Reproduce denied calls with remote-shaped URL and injected query spies, proving zero DDL/lock/provider attempts; exercise permitted test sandbox with fake clients; run one or two adjacent existing suites through `scripts/testing/run.mjs`, server typecheck, scoped lint and diff check. Retain any failing-before result separately. Rollback to a previous deploy artifact is allowed only with these legacy functions disabled or made unreachable; never restore implicit remote-development DDL. This patch alone cannot accept R2-02, reconcile applied 045/047 migration history, or establish staging/production readiness.

**First-function review checkpoint:** Antigravity's initial `ensureMarketingSchema()` guard read mutable `process.env.DATABASE_URL` instead of the URL captured by the pool at import. An [independent adversarial test](../audits/cr1-remediation/r2-02/ANTIGRAVITY_DIRECT_EXPORT_REVIEW_2026_10_01.md) failed before correction and proved that a remote-backed pool could enter DDL after the environment was changed. The corrected guard binds to captured `dbUrl`; 15/15 focused/adjacent tests, server typecheck, scoped lint and diff check pass locally. The second export remains open.

**Second-function review checkpoint:** The first `processMetaReconciliation()` candidate repeated the mutable-URL defect and had seven passing but inadequate tests. A fake-pool adversarial test failed against it before a captured-`dbUrl` test-sandbox guard was installed. The old interval was removed because its worker gate excludes tests while the new sandbox gate requires tests. The adversarial plus existing reconciliation/cutover suites passed 16/16; server typecheck, scoped lint and diff check passed. [Review details](../audits/cr1-remediation/r2-02/ANTIGRAVITY_DIRECT_EXPORT_REVIEW_2026_10_01.md). Outstanding legacy-transaction disposition and canonical v2 recovery are not proven by this containment.
