## Source identity and original failure

The Admin listings view contained many enabled single-field controls that called the broad draft-only listing PUT. The Admin management projection omitted `publication_status`, and media review could offer approval before an image had loaded. Status changes had incomplete audit/cache behavior. ## Implemented local behavior

- The Admin inventory now exposes draft-only property, presentation, feature and room tools. Published/unlisted/unknown-state rows show the accepted-state lock. The status badge names the actual state; media review remains available.
- A dedicated draft property editor reloads the current authenticated property, submits only changed fields with exact current-value comparisons, surfaces a stale-write conflict, and avoids a second save while the first outcome is pending. Basic controls cover title, description, type, city, address and amenities; an expandable panel covers paired coordinates, rental mode, house rules and existing SEO fields. A discard confirmation and focus restoration protect unsaved edits. The service validates an explicit field allowlist, locks the parent, reauthorizes the active Admin on the held transaction, and commits the change with its before/after audit receipt. Replaying an already-applied identical value does not add a second receipt.
- Room updates retain the canonical relational and JSON authority and now commit a before/after audit receipt atomically; audit failure rolls back the room edit. Media moderation checks current Admin authority and refuses approval when the evidence cannot be safely viewed.
- Publication status changes commit with an audit receipt. A successful commit returns success even if the later notification fails. Public list responses use `no-store`; Redis cards use a generation counter rather than an unbounded key scan, and cached hits recheck current published IDs so an emergency unlist cannot be served from a stale cached card even if invalidation fails.
- A direct media-moderation API call can no longer approve a stored asset with an empty or unsafe URL; the locked server-side row is validated before any approval, update or audit. This is URL safety, **not** proof of image content, ownership or usage rights.
- The shared session resolver now reads persisted `users.is_active` as well as the current role. A deactivated account loses authenticated authority with HTTP 401, while a missing account-status column fails closed with HTTP 503. Protected mutation services still recheck identity inside their held transactions to fence revocation during a request. Both required and optional authenticated middleware return no-store responses on failed verification. **Migration 048 must be applied and verified before deploying this application code**; reversing that order would fail closed all authenticated sessions.
- The deployed `.env` Neon candidate was inspected read-only and lacks `users.is_active`, which these protected operations require. Numbered migration 048 is a **local candidate**, tested on disposable PostgreSQL, not applied remotely. Original 041–047 source files were copied additively from `origin/main` with unchanged bytes; this does not make the dirty checkout a deployment artifact.

The draft editor deliberately excludes parent capacity and nightly price. The publication validator does not reconcile parent capacity with canonical room capacity, and accepted pricing/booking facts need a versioned successor rather than an in-place overwrite.

## Still open before “complete Admin control”

1. Accepted/published and unlisted property facts cannot yet be changed through a reviewed immutable successor. The Founder-facing choice about Host acceptance and independent Admin release is pending; no UI shortcut may bypass booked terms, historical quotes or campaign bindings.
2. The primary Neon role/schema remain unready for this feature. Migration 048 needs a named target, checksum reconciliation, restricted-role grant/route rehearsal, and deployment preflight **before** the session resolver change reaches production. Production currently cannot be inferred from local test success.
3. `admin_audit_logs` listing rows lack database-enforced immutability. The Admin inventory is limited to the newest 200 properties, so pagination/search is needed before it can honestly claim access to every property at scale.
4. Publication review still needs verified rights/facts and an accepted-offer contract beyond the current room-photo minimum. The current validator counts approved room-bound assets as photos without an independently verified media-type/content fact; existing assets or other writers can therefore still satisfy its count with non-image evidence. Desktop/mobile real-browser review and deployed three-role tests are outstanding.

Rollback is scoped: disable the new draft editor/route and retain committed audit facts. If migration 048 is later applied, treat it as forward-only and do not edit applied bytes. Never restore broad published-property writes or delete audit history as a rollback.
