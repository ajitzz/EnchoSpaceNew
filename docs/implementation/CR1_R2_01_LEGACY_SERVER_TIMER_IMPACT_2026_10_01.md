# R2-01 legacy server timer containment — impact before code

**Verified source and risk.** `server.ts` loads `.env`, selects a database URL, and sets `shouldRunBackgroundWorkers` true in a long-running development server unless a disable flag is supplied. That value schedules legacy interval jobs, including `processMetaReconciliation`, which can read Meta credentials and query/mutate its selected database. `npm run dev` uses `tsx server.ts`; the primary `.env` names a remote Neon database, not a disposable local fixture. Production and serverless runtimes currently disable these intervals. The canonical dedicated marketing worker is a different entry point.

**Source of truth and scope.** Change only the legacy `server.ts` interval gate. Default it off. Permit opt-in only with exact `HARVO_LEGACY_SERVER_WORKERS_ENABLED=local-disposable-only`, a non-production/non-test long-running process, no serverless host marker, and a syntactically valid PostgreSQL URL whose hostname is loopback. Do not inspect, print, or change secret values; do not alter the dedicated marketing worker, public routes, migrations, financial commands, or provider adapters. This guard prevents accidental **legacy timer execution** against the primary remote `.env`; it does not stop the web server itself from connecting to that database or executing any other startup path. A loopback proxy to a remote service cannot be detected from a URL alone and remains an operator risk.

**Compatibility and security.** Development `npm run dev` no longer starts legacy intervals by default. A developer running an intentional disposable local database can opt in explicitly. Existing direct unit/integration calls to exported worker functions remain available; this does not certify their behavior or authorize live provider actions. No automatic migration of old reconciliation state occurs. The legacy worker code still requires separate retirement/replacement review.

**Validation.** Exercise the gate with absent/incorrect opt-in, primary remote-style Neon URLs, malformed/dummy URLs, production/test/serverless contexts, and explicit local PostgreSQL targets; run relevant targeted legacy-boundary/FSM suites, server TypeScript, scoped ESLint and diff check. Keep test runner credential scrubbing active. No remote database or provider call.

**Rollback/containment.** If local development truly needs the legacy intervals, use only the explicit local-disposable opt-in with a fresh disposable database and fake provider transport. Do not revert to automatic timers with the primary `.env`. If dedicated production worker behavior regresses, revert this isolated server gate only after confirming the worker entry point actually imports it; it currently does not.

**Local implementation receipt (1 October).** `server.ts` now calls the pure gate and logs a truthful disabled/enabled reason without printing the target. Eight target/runtime cases plus the adjacent legacy state/audit test passed **20/20** across two focused files under the sanitized Node 24 runner. Server TypeScript, scoped ESLint and `git diff --check` exited 0. The check did not start `npm run dev`, connect to Neon, execute a provider call or prove that every exported legacy worker is safe for direct invocation. R2-01 remains `IN_PROGRESS` and the primary `.env` remains a prohibited migration/staging target.
