# R4-01 legacy Meta lead ingress containment — 1 October 2026

**Impact before code.** The canonical signed marketing-v2 Meta webhook is mounted before `legacyMarketingBoundary`. Three later legacy paths are still outside that boundary: `/api/marketing/meta/webhooks`, `/api/meta-webhooks`, and `/api/marketing/webhooks/meta-leads`. Their handlers acknowledge lead events while using separate legacy lead rows, placeholder contact values, and/or logs that describe SMS/Push dispatch without a durable delivery. They bypass the canonical conversation/outbox receipt path and can create misleading host operations evidence. This is a source finding, not proof that Meta is currently configured to call these URLs.

**Scoped change.** Classify only those three POST legacy paths as retired `MARKETING_AUTOMATION` operations using the existing boundary. Keep `/api/webhooks/marketing/v2/meta` unchanged. No database, payment, provider credential, active campaign, or notification worker is modified. The legacy handlers remain in source for historical review but are unreachable through these routes after the boundary.

**Security and compatibility.** Blocking fake acknowledgements is fail-closed. Any externally registered legacy callback must be moved through an approved, canonical v2 lead-ingestion design; this patch does **not** assert that v2 currently provides native lead-form CRM conversion. If old callbacks are still registered, they will receive HTTP 410 and can lose/queue events according to provider behavior. That configuration must be inventoried before a live rollout. There is no customer-message authorization in this change.

**Validation and rollback.** Add failing-before mounted HTTP tests for each route, then pass boundary and mounted tests under the sanitized Node 24 runner. Verify canonical v2 exemption in the existing boundary test, scoped lint/typecheck and diff check. Rollback only after a reviewed replacement ingress exists; reopening the simulated lead handlers is not an acceptable recovery path. R4-01 remains open for real durable notification intents, consented external delivery, privacy retention and mounted preference/evidence APIs.

**Local result.** The three new mounted cases failed before repair with HTTP 403 from the old signature middleware, proving the handlers were reachable. After adding the three paths to `legacyMarketingBoundary`, the mounted and boundary suites passed 30/30. The existing v2 exemption stayed 204 in the boundary fixture. Node 24 client/server typecheck, scoped ESLint and `git diff --check` exited 0. These tests use synthetic requests; they do not establish what URL Meta currently calls, a real lead-ingestion replacement, or a notification-channel delivery receipt. Keep R4-01 `IN_PROGRESS`.
