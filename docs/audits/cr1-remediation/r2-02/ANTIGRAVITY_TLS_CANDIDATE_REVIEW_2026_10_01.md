# R2-02 runtime TLS candidate — independent review in progress

**State: CHANGES_REQUESTED.** This is a review of the current shared-checkout candidate, not acceptance of R2-02 or a production incident claim. Antigravity added `src/server/deployment/databaseTls.ts`, a focused test, and wiring in `server.ts` and the dedicated marketing worker. The proposed remote URL normalization is useful: it turns the deployed `sslmode=require` input into `verify-full` in memory and rejects several downgrade modes. The main server's old `rejectUnauthorized:false` option was removed from its normal valid-URL path.

**Reproduced fail-open defect.** At review time, `server.ts` catches invalid primary or read-replica URL validation, sets the affected pool's `connectionString` to `undefined` and `ssl` to `false`, then still calls `new Pool(...)`. `pg` treats an undefined connection string as permission to use ambient `PGHOST`/`PGDATABASE` or its defaults. A no-network `pg/lib/connection-parameters` check with synthetic `PGHOST=unexpected.internal` resolved `host: unexpected.internal`, `ssl: false`. The correct behavior is to avoid constructing any connectable pool from a rejected configured target, with an explicit unavailable error path. A regression must demonstrate no fallback for both write and read targets. This finding is not covered by the candidate's URL-helper tests.

**Remaining review points.** Permit only known safe remote URL query keys so parser options such as `sslrootcert` or session `options` cannot silently alter trust or authority. `encho-test.invalid` is a synthetic test target, not a loopback address; plaintext permission should require the explicit credential-scrubbed test context. The AdTech worker and operator CLI have separate pool constructors outside this bounded candidate. Verify actual `pg` connection parameters and ideally a local rejected-certificate handshake after correction. No external database connection or migration apply is authorized by this review.

**Later candidate revision, 1 October:** The shared checkout now uses `createFailClosedPool()` after rejected primary/read URL validation instead of constructing a connectable pool with an absent connection string. The helper also allowlists remote URL query keys and restricts `encho-test.invalid` to the explicit test sandbox. Its focused TLS and two direct-export suites passed 45/45 on Node 24, including an ambient-`PGHOST` negative case; typecheck and lint passed on the working tree. These results retire the *specific first-candidate fallback reproduction* for the revised code, but are not a whole-runtime or R2-02 acceptance: the isolated staged tree, other pool constructors, real certificate rejection, deployed credentials and full release checks require separate evidence. Preserve the failed first-candidate finding above as history.
